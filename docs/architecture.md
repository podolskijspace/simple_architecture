# Архитектура приложения

Документ определяет структуру компонентов, разделение ответственности между View
и Presenter, правила декомпозиции, размещения файлов и импортов.

## Статус

Документ формируется совместно с автором. Ниже постепенно фиксируются архитектурные решения и правила.

## Исключения из проверки

Файлы `src/index.tsx` и `src/App/App.tsx` не проверяются по архитектурным
правилам этого документа.

Это исключение стоит пересмотреть: определить архитектурные требования к этим
файлам и необходимость их отдельной проверки.

## Точка входа технической логики

В текущем приложении одна страница. На данном этапе `src/Main/Main.tsx`
является точкой входа технической логики приложения.

Это описание текущей структуры. К `Main` применяются общие правила компонентов,
описанные ниже.

## Формат правила

Для каждого правила фиксируем:

- **Правило:** требование к архитектуре.
- **Зачем:** какую проблему оно решает.
- **Область применения:** где оно действует и какие есть исключения.
- **Проверка:** по каким признакам ревьюер определяет соблюдение или нарушение.

Примеры добавляем, когда они помогают однозначно понять правило.

## Структура компонента

Каждый компонент располагается в собственной директории. Имя его View-файла
совпадает с именем директории:

```text
Component/
  Component.tsx        # обязательно: View
  usePresenter.ts     # опционально: Presenter
  Component.module.css # опционально: стили View
```

### View

`{directoryName}.tsx` содержит View компонента. Здесь допустима только логика
отображения, без логики обработки входных параметров.

Если компоненту нужен Presenter, View вызывает `usePresenter` и рисует интерфейс
согласно полученному результату.

### Presenter

Опциональный `usePresenter.ts` содержит Presenter-логику компонента: всю логику
обработки входных и выходных параметров.

При декомпозиции Presenter рядом можно создавать дополнительные хуки. Эти хуки
используются строго внутри `usePresenter` или друг друга. View не вызывает их напрямую.

### Стили

Опциональный `{directoryName}.module.css` содержит стили View и импортируется в него:

```tsx
import styles from './Component.module.css';
```

Здесь `Component` — пример имени директории компонента.

## Размер файлов и декомпозиция

Все файлы компонента, кроме файлов стилей, должны содержать не больше 120 строк.
Если файл превышает этот размер, его необходимо декомпозировать.

View можно разделять на дополнительные компоненты. Они располагаются во вложенных
директориях и следуют тем же правилам структуры, ответственности и размера файлов.

Presenter можно разделять на дополнительные хуки с ограничениями использования,
описанными выше. На эти хуки также распространяется лимит 120 строк.

## Локальные компоненты и импорты

Компоненты, необходимые конкретному View, могут располагаться непосредственно
в его директории, каждый в собственной вложенной директории:

```text
Component/
  Component.tsx
  Child/
    Child.tsx
```

Локальные файлы импортируются по относительному пути. Например, в `Component.tsx`:

```tsx
import { Child } from './Child/Child';
```

## Переиспользуемые компоненты

Для переиспользуемых компонентов можно создавать директорию `components`.
Каждый компонент внутри неё сохраняет собственную директорию и общую структуру.

### Общие для приложения

Компонент, используемый по всему приложению, хранится в `src/components`.
Импорт из этой директории — абсолютный. В текущем проекте здесь хранятся только
UI-компоненты.

### Общие для ветви дерева

Если компонент переиспользуется внутри определённой ветви, он располагается
в `components` ближайшего общего родителя использующих его компонентов.
Импорты остаются относительными.

Например, `Component3` и `Component4` используют `Shared`:

```text
Component/
  Component.tsx
  Component2/
    Component2.tsx
    components/
      Shared/
        Shared.tsx
    Component3/
      Component3.tsx
    Component4/
      Component4.tsx
```

В `Component3.tsx` и `Component4.tsx`:

```tsx
import { Shared } from '../components/Shared/Shared';
```

## Проверка при ревью

Перед проверкой учитывай раздел «Исключения из проверки».

- У каждого компонента есть View-файл с именем его директории.
- View содержит только логику отображения; обработка входных и выходных параметров
  находится в Presenter.
- При наличии Presenter View вызывает его и использует результат для отображения.
- Дополнительные хуки Presenter вызываются только из `usePresenter` или друг друга.
- Файлы, кроме стилей, не превышают 120 строк.
- Вложенные и переиспользуемые компоненты следуют тем же правилам структуры.
- Общие компоненты размещены согласно области использования: в `src/components`
  либо в `components` общего родителя внутри ветви.
- Локальные импорты относительные; импорты из `src/components` абсолютные.
- Стили View при наличии находятся в `{directoryName}.module.css` и импортируются во View.
